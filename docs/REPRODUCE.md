# REPRODUCE — every figure and every number, traced to source

This is the referee's map. **Every plotted number is committed as a `.json`/`.dat` file**, and every figure
is regenerated from it by a `make_*.py` script (native pgfplots — no hand-typed values). To rebuild a
figure's data *from scratch* (exact diagonalization), run the **compute** script in the same row first.

All scripts live in [`../src/`](../src/) and all committed data in [`../data/`](../data/), with the
environment of [`requirements.txt`](../requirements.txt). The two-step pattern is:
`python src/<compute>.py` → writes `data/<data>.json` → `python src/make_<fig>.py` → writes
`paper/figs/<fragment>.tex` → `make paper`.

> **Where the output goes (changed 2026-09-18).** Every compute script now resolves its output path from
> **its own location on disk**, so `data/` means *this clone's* `data/` no matter what directory you are
> standing in. Pass `--out PATH` to send it somewhere else, `--in PATH` to read from somewhere else.
> Until 2026-09-18 eighteen of these scripts wrote to `/w/`, the working directory of the container the
> original runs were made in: **following these instructions did not repopulate `data/`, and this
> document was not true.** See [`KNOWN_DISCREPANCIES.md`](KNOWN_DISCREPANCIES.md) §2 for the repair and
> the evidence that it works.

**Reproduce everything at once:** [`../notebooks/00_Reproduce_Everything.ipynb`](../notebooks/00_Reproduce_Everything.ipynb)
(or `make reproduce`) runs the whole pipeline as one narrated, top-to-bottom notebook — every figure and
number below, each loaded from the same `data/*.json` that feeds the paper.

**The guardian (≈15 s, numpy/scipy only):** `python src/verify.py`. It recomputes `F₁(L=6)` for the open
chain (9.6047, the resource families) and the periodic ring (9.3851, the scaling figure) and the geminal
witness (`F₁=F₂=4K`, `|S|=2^K`, `χ=2`) by exact diagonalization — and then checks roughly 4 900 numeric
assertions over the deposited `.json`, `.dat` and `.tex`, including `paper/main.tex` (the abstract), against
those recomputed values. It exits non-zero and names the defect. The `[XFAIL]` lines are registered open
defects and open claims: they are printed on purpose and do not set the exit code.
`python src/check_figures.py` additionally re-runs **six** of the twenty figure generators into a scratch
tree and diffs the result against the committed fragments (7 artefacts). Six, not every: ten figures have no
deposited source at all, `make_scaling_fig.py` is excluded on purpose because it would destroy the committed
Fig. 12 (§3 of `KNOWN_DISCREPANCIES.md`), and the remaining generators write `.dat` files that no committed
fragment reads back.

> **`--fast` certifies nothing.** It skips the `L=10` diagonalisations and therefore the checks that depend
> on them, and it exits 3 even when nothing fails. Use it while editing; never quote it.

> **Honesty note.** The committed `paper/figs/*.tex` and `*.pdf` are **authoritative** and match `main.pdf`.
> Every plotted *number* comes from the committed `.json`/`.dat`. Two fragments received manual annotation
> placement *after* generation — the resource-master annotation (Fig. 2) and the added absolute-cost panel (c)
> of Fig. 12; for those the committed `.tex` is the source of truth. The hardware panel (Fig. 15b) is fully
> regenerated by `src/make_hardware_hero.py` from `data/hw_lucj_n2_result.json`: the solid curve is the **mean
> over the 8 recovery seeds** and the **shaded envelope** is the ±1 s.d. spread across those 8 seeds at every
> step (`dE_hist_mean` / `dE_hist_std`, reconstructed from the full per-seed run log of job `da125f2ein7c73bcsqs0`).
>
> **Where this deposit and its own code disagree — and there are places — is written down in
> [`KNOWN_DISCREPANCIES.md`](KNOWN_DISCREPANCIES.md)**: the η = 0.18 / 0.20 mismatch in `S(q,ω)`
> (now guarded — the script **refuses to run**, exit 2, rather than spend 726 s and then overwrite the
> deposited spectrum at the wrong η; pass `--eta 0.18`, or `--out` somewhere else, or `--force-eta`),
> the scaling-figure generator that is
> out of sync with the committed figure, and the ten figures whose `.tex` source is not deposited.
> Read it before re-running any compute script.

## Compute engines (shared)

- **`akw_lanczos.py`** — sector-basis (up-string ⊗ dn-string) Hubbard engine: sparse ground state, Haydock
  continued fraction for `G(z)`, `c†_k`/`c_k` maps. Reused by `sampled_akw.py`, `scaling_data.py`.
- **`scaling_lanczos_mf.py`** — fully matrix-free, RAM-staged, resumable (checkpoints to `ckpt/`) to reach
  L=14 (28 qubits) on a memory-limited machine.

## Environment & caveats (honest)

- Exact-diagonalization figures reproduce **locally in seconds–minutes**. `scaling_lanczos_mf.py` at L=14
  needs staged runs (see its docstring); L=16 is physically infeasible on a workstation.
- Figures compile with any TeX distribution (TeX Live / MiKTeX) + `pgfplots ≥ 1.18`.
- The two IBM Heron runs need an IBM Quantum account, **and so does re-running their classical
  post-processing**. Corrected 2026-09-18: this document used to say the notebooks "ship with cached device
  counts". They do not. `HW_LUCJ_N2_Heron_READY.ipynb` obtains its counts with `result_hw = job.result()[0]`
  (under the comment `job = service.job('PASTE_JOB_ID_HERE')`) and `Spectral_Heron.ipynb` with
  `res = job.result()` → `get_counts()`: the bitstrings come over the network from the IBM Quantum service.
  **No raw bitstring or count is anywhere in `data/`** — what is deposited is the post-processed arrays plus
  the backend, shot count and job id. So the recovery and the Lehmann reconstruction cannot be re-run from
  the deposit alone; what can be re-checked offline is every plotted number against the file it came from.
  Credentials are **not** included — insert your own (see the security note in the README).

## What a clean clone can and cannot reach — measured, not asserted

Everything below was run on 2026-09-18 on a Windows workstation with Python 3.11, numpy and scipy, no
`pyscf`, no TeX in the loop, and **no `/w` directory of any kind**.

### Reaches the paper's numbers

| command | result |
|---|---|
| `python src/verify.py` | **PASS** — 801 checks, 0 failures, 11 registered xfail, 2 skips, 5 014 numeric assertions, 12.3 s |
| `python src/check_figures.py` (`make check-figures`) | **PASS** — all 7 regenerated artefacts byte-identical to the committed ones |
| the six commands of the `figures` recipe, run in order | **exit 0** on all six, and the regenerated fragments are byte-identical |
| the two commands of the `data` recipe, run in order | **exit 0** — rebuilds `paper/figs/sqw_edges.dat` and `data/charge_gap.json` from the deposited spectra (~4 min, L=4…12 exact diagonalization) |
| `python src/sqw_lanczos.py 12 --eta 0.18` | reproduces `data/sqw_L12.json` byte for byte — see `KNOWN_DISCREPANCIES.md` §12. Without `--eta 0.18` the script now **exits 2 and computes nothing**, instead of running for 726 s and overwriting the deposit at η = 0.20 |
| `python src/akw_lanczos.py <L>`, `src/spin_lanczos.py`, `src/sampled_akw.py`, `src/scaling_data.py`, `src/ladder_vs_chain.py`, `src/spectral_validation_max.py` | run with numpy/scipy only; minutes at the deposited sizes |
