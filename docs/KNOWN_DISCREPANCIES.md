## 1. `S(q,ω)`: the deposited data is η = 0.18 t, the script's default is η = 0.20 t — **OPEN by design, now guarded**

| where | value |
|---|---|
| `data/sqw_L12.json` → `"eta"` | **0.18** |
| `src/sqw_lanczos.py:21` → `def run(..., eta=0.20, ...)` | **0.20** |
| `src/sqw_lanczos.py:43-45` → `d = run(L=L)` (no `eta` passed) | uses the default, **0.20** |
| the manuscript, for this figure (`results.tex:93`) | **η = 0.18 t** |

**Stated plainly: running `python src/sqw_lanczos.py 12` exactly as `REPRODUCE.md` documents it
produces a spectral function with a different Lorentzian broadening from the one deposited and
plotted** — FWHM 2η = 0.40 t instead of 0.36 t. Peak positions are unaffected; peak heights,
linewidths, and every band-edge/onset number read off the curve are. `figs/sqw_edges.dat` is derived
from the deposited η = 0.18 raster, so it will not match a fresh η = 0.20 run either.

Corroborating evidence that the η = 0.20 run once existed and was superseded: `FIGURE_PROVENANCE.md`
lists `sqw_L12_eta020_backup.json` in its STALE list.

**What was done about it on 2026-09-18, and why the default was *not* changed.**
The deposited η = 0.18 raster is the authoritative artefact. Flipping the default to 0.18 would make the
script agree with the deposit — but `data/sqw_L12.json` would then be a file *nobody had regenerated*
under the new default, and the one-token edit would be indistinguishable, in the diff, from someone
quietly changing a published number. So the default stays at 0.20, exactly where the published runs left
it, and two things were added instead:

1. **`--eta` is now a command-line argument.** `python src/sqw_lanczos.py 12 --eta 0.18` reproduces the
   deposited file. The reader no longer has to edit source code to reproduce the deposit.
2. **The script refuses to be quiet about it.** Before computing anything it reads the `"eta"` of the
   deposited `data/sqw_L{L}.json` and, if the run about to start uses a different one, prints:

   ```
   ==============================================================================
   WARNING: running at eta=0.2 but the DEPOSITED sqw_L12.json has eta=0.18.
            This run will NOT reproduce the deposited file, nor the eta the paper
            quotes. Re-run with:  python src/sqw_lanczos.py 12 --eta 0.18
   ==============================================================================
   ```

**Verified end-to-end 2026-09-18:** `python src/sqw_lanczos.py 12 --eta 0.18` was run from a clean
checkout on a machine with no `/w`, and its output was compared against `data/sqw_L12.json` — see §12.

Status: **the mismatch between the default and the deposit is still real and still documented, but it
can no longer bite silently, and the deposit can now be reproduced from the command line.**

The sibling channels were checked and are both **consistent**:

- `src/akw_lanczos.py:99` defaults to `eta=0.15`, but its `__main__` (`:138`) passes `eta=0.18`
  explicitly, matching `data/akw_lanczos_L12.json` (`"eta": 0.18`). No discrepancy.
- `src/spin_lanczos.py:17` sets `eta=0.10`, matching `data/spinqw_L12.json` (`"eta": 0.1`). No discrepancy.

## 2. Eighteen scripts in `src/` wrote their output to `/w/` — **REPAIRED 2026-09-18**

`/w/` was the working directory of the Docker container the published compute ran in. It does not exist
on a reader's machine and it is not `data/`. **The documented pipeline therefore did not repopulate
`data/` — the deposited files were moved there by hand.** That is the defect that mattered most in this
whole deposit: every other document in `docs/` told the reader to run a command that could not produce
what it claimed to produce.

**What was changed.** Eighteen files received one identical, self-contained block (search any of them for
`DEPOSIT PATHS`) and their `/w/...` literals now go through it:

```python
_REPO = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
_outpath(name)              -> <repo>/data/<name>     override: --out PATH
_outpath(name, sub='build') -> <repo>/build/<name>    (by-products that are NOT deposited)
_inpath(name)               -> <repo>/data/<name>     override: --in  PATH
```

The default is anchored to the **file's own location**, not to the working directory, so the scripts
work from any `cwd` and from any clone path. `--out` / `--in` take precedence and are resolved against
the current directory. **Nothing but paths was touched: no physics, no computational default.**

## 14. ARPACK was seeding itself at random -- **REPAIRED 2026-09-18**

`src/scaling_lanczos.py` and `src/scaling_lanczos_mf.py` called `scipy.sparse.linalg.eigsh` with no
`v0=`. ARPACK then draws its own start vector from an **unseeded** generator, so `E0` converges to a
slightly different point on every run, and every `rel-L1` computed against it moves with it. Measured on
`L = 6` before the repair -- three consecutive calls, same matrix, same machine:

```
unseeded : -2.0481308860914536   -2.0481308860914504   -2.0481308860914522
seeded   : -2.0481308860914567   -2.0481308860914567   -2.0481308860914567
```

The last three digits genuinely move. Six `eigsh` call sites now pass a fixed, dimension-dependent start
vector (`_v0`, `default_rng(20260918)`), which makes them bit-reproducible. Deliberately **not** a global
`numpy` seed: this touches the ARPACK start vector and nothing else.

**Consequence a reader must know:** a re-run with the fixed `v0` need not land on the *same last digits*
as the deposited values, which were produced by unseeded runs. It will agree to ARPACK's tolerance
(~1e-13), which is far below any quoted precision, and from now on it will agree with *itself*.

## 16. The eta guard warned but did not refuse -- **REPAIRED (second pass)**

The guard added in the morning (SS1) printed a warning and then ran anyway. Demonstrated consequence: a
reader who types the documented command `python src/sqw_lanczos.py 12` waits 726 s and **the deposited

It now **refuses**: if the run would overwrite a deposited file that was made at a different eta, it

with no escape becomes a guard people delete:

| what you want | command |
|---|---|
| reproduce the deposit | `python src/sqw_lanczos.py 12 --eta 0.18` |
| explore another eta | `python src/sqw_lanczos.py 12 --out <path outside data/>` |
| overwrite on purpose | `python src/sqw_lanczos.py 12 --force-eta` |

Measured: the bare command exits 2 and `data/sqw_L12.json` keeps its original timestamp.
